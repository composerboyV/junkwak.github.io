보안 작업

프로젝트마다 무엇을 막았고, 어떻게 했고, 어떻게 확인했는지 모았습니다.

저장소 코드와 커밋, 테스트 기록, 배포 점검 기록에서 확인한 것만 적었습니다. 제가 직접 만든 부분만 담았고, 팀원 작업은 뺐습니다. 공개 문서라 서버 주소·키와 아직 고치지 않은 약점은 적지 않았습니다.

01 42 Asia Hackathon 2026 in Tokyo TEAM Mirai · 웹 플랫폼·인프라 담당 부분

제가 맡은 웹 서버·인프라·채널 연동 부분만 적었습니다. A1·A2 에이전트는 팀원 작업이라 뺐습니다. 프로젝트 보기 ↗

  1. 비밀번호 안전 저장

    막는 것
    비밀번호 유출·대입 공격
    한 일
    비밀번호를 scrypt(무작위 솔트, 파라미터 함께 저장)로 해시하고 비교는 시간 일정 비교로 합니다. 없는 이메일도 같은 시간만큼 계산해 계정 존재 여부가 응답 시간으로 드러나지 않게 했습니다. 가입·로그인은 IP와 이메일별로 횟수를 제한합니다.
    확인
    단위 테스트(맞는 비밀번호 통과, 틀린 비밀번호 거부, 같은 비밀번호도 매번 다른 해시)

  2. 세션 쿠키 보호

    막는 것
    세션 탈취·도용
    한 일
    256비트 무작위 토큰을 쓰고, DB에는 토큰 원문 대신 서버 비밀값으로 만든 HMAC 값만 저장합니다. 쿠키는 HttpOnly·SameSite·Secure·__Host- 접두어를 씁니다. 로그아웃하면 세션을 폐기합니다. 직원 계정은 비밀번호를 다시 발급하면 기존 세션을 모두 폐기합니다.
    확인
    단위 테스트(토큰 길이·무작위성, 쿠키 속성 문자열)

  3. 다른 사이트에서 보내는 요청 차단(CSRF)

    막는 것
    사용자가 모르게 다른 사이트에서 상태 변경 요청
    한 일
    GET이 아닌 모든 API 요청은 같은 출처인지(Sec-Fetch-Site, Origin) 확인하고 JSON 본문만 받습니다. 본문 크기도 제한합니다. 직원 화면은 다른 사이트 안에 넣어 띄울 수 없게 했습니다.
    확인
    서버 테스트(다른 출처 POST → 403, JSON 아님 → 415)

  4. 외부 주소로의 이동 차단

    막는 것
    로그인 후 이동 주소를 조작해 다른 사이트로 보내는 것
    한 일
    이동·저장 경로는 이 사이트 안의 경로만 받습니다(//로 시작하는 주소, 백슬래시, 제어 문자 거부).
    확인
    단위 테스트(//evil.example, 백슬래시 형태, 외부 https 주소 모두 거부)

  5. DB 최소 권한

    막는 것
    앱 계정이 탈취돼도 피해 범위 축소
    한 일
    앱 실행 계정은 자기 DB에서 읽기·쓰기·삭제만 할 수 있고 테이블 생성·변경 권한은 없습니다. 앱은 관리자 계정이나 다른 DB 설정이 들어오면 연결을 거부하고, TLS 1.2 이상만 씁니다. DB 오류는 코드만 기록해 접속 정보가 로그나 응답에 나오지 않습니다. 권한 설정 스크립트가 끝에서 "다른 DB 접근 거부, DDL 거부, TLS 없는 연결 거부"를 직접 시도해 확인합니다.
    확인
    단위 테스트(TLS 필수, 관리자 계정·다른 DB 거부) + 설정 스크립트의 자체 점검

  6. 배포 비밀값 최소화

    막는 것
    배포용 장기 비밀번호 유출
    한 일
    GitHub Actions에서 Azure로 배포할 때 OIDC 임시 토큰으로 로그인하게 해 배포 프로필이나 클라이언트 비밀을 저장하지 않습니다.
    확인
    워크플로 파일 확인(배포 성공 여부는 저장소 안에 기록 없음)

  7. WhatsApp 웹훅 검증

    막는 것
    위조된 메시지 요청, 같은 메시지 반복 처리, 폭주
    한 일
    연결 확인 토큰을 시간 일정 비교로 확인하고, 들어오는 메시지마다 앱 비밀값 HMAC 서명을 검사해 틀리면 401로 거부합니다. 본문은 1MB까지만 받고, 우리 번호로 온 사용자 메시지만 처리합니다. 같은 메시지 ID는 한 번만 처리하고, 보낸 사람별로 1분 15건까지만 답합니다. 설정이 없으면 503으로 꺼집니다.
    확인
    단위 테스트(토큰 없는 연결 확인 거부, 서명 없음·틀린 서명 거부, 다른 번호 메시지 무시)

  8. 외부 AI 리뷰로 찾은 문제 수정

    막는 것
    승인 안 된 문안 발송, 회원이 AI 결과를 꾸며 넣는 것
    한 일
    다른 AI(Codex)에게 읽기 전용 리뷰를 맡기고 17건을 모두 고쳤습니다. 제안 문안은 행 잠금 트랜잭션 안에서 승인·발송하고, 직원이 화면에서 본 문안의 해시가 맞아야 승인·발송됩니다. 회원이 AI 결과를 쓰던 API는 없애고 서버에서만 기록합니다.
    확인
    수정 후 실서버에서 10가지 요청을 직접 시도해 기대한 거부 코드 확인(문서 기록), 당시 테스트 26개 통과

02 BidScope 나라장터 입찰 검토 에이전트

외부 문서와 LLM을 다루는 에이전트라 입력과 AI 행동 범위를 좁혔습니다. 프로젝트 보기 ↗

  1. 외부 파일 가져오기 주소 제한

    막는 것
    서버가 내부망·임의 주소로 요청을 보내게 만드는 공격(SSRF)
    한 일
    공고 첨부는 나라장터 공개 도메인의 HTTPS 주소만 허용합니다. 사용자 정보가 붙은 주소, 다른 포트, 비슷한 가짜 도메인은 거부합니다. 리디렉션은 최대 3번, 매번 같은 검사를 다시 합니다. 받은 파일은 30MB 이하, PDF 시작 표식이 있어야 합니다.
    확인
    테스트: 127.0.0.1, 가짜 도메인, file:// 주소가 네트워크 요청 전에 거부됨. localhost로 가는 리디렉션 거부, PDF 아닌 파일 거부 후 남는 파일 없음

  2. 업로드 파일 검증

    막는 것
    악성·잘못된 파일 업로드, 경로 조작
    한 일
    확장자 .pdf, 30MB 상한(받는 중에 끊음), PDF 시작 표식을 확인합니다. 임시 파일에 먼저 쓰고 읽기에 성공해야 내용 해시(sha256) 이름으로 저장합니다. 원래 파일 이름은 경로를 떼고 이름만 씁니다.
    확인
    테스트: PDF 아닌 내용·.hwp 거부(422), ../공고.pdf → 공고.pdf

  3. API 키 비보관

    막는 것
    모델 API 키 유출
    한 일
    사용자가 넣은 키는 작업 하나의 메모리에만 두고, 요청 기록·작업 상태·SQLite에는 넣지 않습니다. 작업이 끝나면 메모리의 키도 지웁니다.
    확인
    테스트: 응답·작업 상태·저장된 결과·DB 전체에서 키 문자열이 나오지 않고, 끝난 뒤 키 값이 빈 문자열

  4. 오류 메시지로 비밀이 새지 않게

    막는 것
    오류 응답·로그에 키나 내부 정보 노출
    한 일
    입력 검증 오류는 위치·메시지·종류만 돌려주고 입력값은 빼고 돌려줍니다. 공공데이터 API 오류는 결과 코드만 보여 주고 원문 메시지는 숨깁니다. 모델 호출 오류도 정리된 문장만 남깁니다.
    확인
    테스트: 검증 오류 응답에 키 없음·input 필드 없음, 공공 API 오류 원문이 메시지에 안 나옴

  5. 설정 파일 허용 목록

    막는 것
    설정 파일을 통한 다른 환경 변수 덮어쓰기·변수 치환
    한 일
    설정 파일에서는 정해진 7개 이름만 읽고, 변수 치환은 하지 않으며, 이미 있는 환경 변수를 덮어쓰지 않습니다.
    확인
    테스트: 목록 밖 이름 무시, ${HOME}이 그대로 남음, 기존 값 유지

  6. AI 행동 범위 제한

    막는 것
    모델이 정해지지 않은 도구를 부르거나 예제 경로로 실제 자료를 처리
    한 일
    모델 응답의 행동은 회사 자료 검색·페이지 읽기·종료 세 가지만 스키마로 허용합니다. 예제(가짜 모델) 모드는 합성 자료만 받습니다.
    확인
    테스트: 목록 밖 행동(send_slack) 거부, 실제 자료로 예제 모드 거부

  7. 로컬 전용·작업 수 제한

    막는 것
    외부에서 접근, 작업 폭주
    한 일
    허용 호스트를 127.0.0.1·localhost로 묶었습니다. 동시에 진행되는 검토는 3개까지, 한 번에 하나씩 실행합니다. 모델 호출 횟수(120회)·입력 길이 상한을 넘으면 멈춥니다.
    확인
    테스트: 대기열 상한·취소, 예산 초과 시 성공으로 표시 안 됨(호스트 제한은 코드 확인만)
