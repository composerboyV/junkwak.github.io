Coupang Order Viewer

쿠팡 주문과 배송지를 모아 보고 엑셀로 저장하는 Windows 앱

쿠팡 주문 메일에서 상품과 배송지 정보를 모아 보여주는 Windows 앱입니다. 주문을 주소·수취인·상품별로 확인하고 엑셀 파일로 저장할 수 있습니다.

담당 범위
개인 프로젝트 · Windows 데스크톱 앱(WPF · .NET 8) 개발
실행 형태
별도 서버 없이 내 PC에서 실행합니다. 주문과 설정은 PC에 저장하고, 메일 비밀번호는 DPAPI로 암호화합니다.

목차 CONTENTS

01 문제 PROBLEM

공동구매를 할 때마다 쿠팡 주문 메일을 하나씩 열어 배송지와 수량을 옮겨 적어야 했습니다. 주문 메일을 한곳에 모아 확인하고, 필요한 정보를 엑셀로 바로 내보내는 도구를 만들기로 했습니다.

02 결정 DECISION

주문 조회 API가 없어 주문 메일을 읽었습니다

처음에는 쿠팡 판매자 API를 기준으로 주문 조회부를 설계했지만, 구매자가 자기 주문을 조회할 수 있는 API는 없었습니다. 그래서 MailKit으로 주문 메일을 IMAP으로 읽는 방식으로 바꿨습니다. 화면과 주문 병합 로직은 주문 출처 인터페이스(IOrderApiClient)만 보게 두어, 그 뒤의 수집 방식만 메일로 바꿔 끼웠습니다.

새 메일만 받고, 지난 주문은 PC에 쌓았습니다

폴더마다 마지막으로 읽은 메일 위치(UID)와 처리한 Message-ID를 기억해 새 메일 헤더만 받습니다. 네이버 IMAP의 기간 검색은 최근 몇 달 치만 돌려줘서, 60일이 넘는 기간은 전체를 훑은 뒤 날짜를 코드에서 거릅니다. 이미 처리한 메일은 다시 받지 않으므로, 같은 주문번호는 최신본만 남기고 배송지가 바뀌면 이전 주소와 함께 표시해 PC에 쌓아 둡니다.

메일 형식이나 계정이 달라도 주문이 섞이지 않게 했습니다

쿠팡 메일은 시기마다 HTML 구조와 마스킹 방식이 달라서, 표 구조를 줄바꿈으로 살린 뒤 상품 줄을 네 가지 형식으로 차례로 읽습니다. 상품을 찾지 못한 메일은 주문 메일이 아닌 것으로 보고 버립니다. 또 한 파일을 같이 쓰다 두 메일 계정의 주문이 섞이는 문제를 발견해, 주문 파일과 메일 캐시를 계정별로 나눴습니다.

엑셀은 바로 쓸 수 있게, 비밀번호는 Windows 계정에 묶었습니다

ClosedXML로 상품 한 개당 한 행씩 엑셀을 만들고, 배송지가 바뀐 주문 행은 붉은 배경으로 표시합니다. 메일 비밀번호는 Windows DPAPI(현재 사용자 범위)로 암호화해, 설정 파일이 복사돼도 같은 Windows 계정이 아니면 풀 수 없습니다.

03 구조 ARCHITECTURE

조회를 누르면 주문 병합 단계가 주문 출처 연결부를 거쳐 IMAP 수집과 주문 메일 파서를 부르고, 합친 주문을 계정별 JSON에 저장합니다. 메인 창은 이 주문으로 주소·수취인·상품별 묶음을 계산하고, 엑셀 저장도 같은 주문 목록을 씁니다. 별도 서버 없이 PC 안에서 처리합니다.

04 결과 RESULT

주문 메일을 받아 주소·수취인·상품별로 묶어 보고, 같은 주문이 다시 오면 최신본으로 합치며, 배송지가 바뀐 주문은 표시한 채 엑셀로 저장할 수 있게 됐습니다. 메일이 잡히지 않을 때는 날짜별 로그에서 어느 폴더의 메일을 몇 개 확인했는지 볼 수 있습니다.
